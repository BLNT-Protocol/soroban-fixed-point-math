# Fixed-point formal verification

This standalone Lean project machine-checks the signed-`I256` arithmetic model and the positive-denominator paths of `src/i256.rs` used by downstream fixed-point consumers.

## Checked claims

| Proof obligation | Lean theorem |
| --- | --- |
| Checked signed 256-bit addition, subtraction, and multiplication return their exact integer result precisely when it is in range | `I256.checked_eq_some_iff`, `I256.add_eq_some`, `I256.sub_eq_some`, `I256.mul_eq_some` |
| Positive-denominator division agrees with truncation toward zero and cannot escape the input's signed 256-bit range | `I256.truncDiv_eq_tdiv`, `I256.ediv_inRange`, `I256.truncDiv_inRange`, `I256.div_eq_some` |
| The source-equivalent remainder corrections compute mathematical floor and ceiling without trapping under their stated range hypotheses | `FixedPointImpl.mulDivFloor_refines`, `FixedPointImpl.mulDivCeil_refines` |
| The public fixed multiplication and division shapes inherit those refinement results | `FixedPointImpl.fixedMulFloor_refines`, `FixedPointImpl.fixedMulCeil_refines`, `FixedPointImpl.fixedDivFloor_refines`, `FixedPointImpl.fixedDivCeil_refines` |

## Scope and assurance boundary

`I256.lean` models observable checked arithmetic with mathematical integers; `none` represents a Soroban host arithmetic error. `FixedPointImpl.lean` mirrors the control flow and arithmetic of the positive-denominator branches in `src/i256.rs`. The proofs establish exact floor or ceiling semantics and absence of arithmetic errors when the product and denominator satisfy the theorem hypotheses.

The Rust-to-Lean correspondence is human-reviewed rather than generated by verified Rust extraction. Soroban host operations are trusted to implement their protocol-specified signed-256-bit behavior. Negative denominators, environment object representation, metering, and storage are outside the current model. Downstream applications remain responsible for proving that their inputs satisfy the range and positive-denominator hypotheses.

## Running the proofs

Install the Lean toolchain selected by `lean-toolchain`, then run:

```sh
cd verification
lake update
lake build
```

The proof sources intentionally contain no `sorry`, `admit`, or custom axioms. CI also audits compiled declarations and permits only Lean's standard `propext`, `Classical.choice`, and `Quot.sound` foundations.
