# Fixed-point formal verification

This standalone Lean project machine-checks the signed-`I256` arithmetic model and positive-denominator paths of `src/i256.rs`, together with the checked signed-`i128` arithmetic and positive-denominator `FixedPoint for i128` paths in `src/i128.rs`.

## Checked claims

| Proof obligation | Lean theorem |
| --- | --- |
| Checked signed 256-bit addition, subtraction, and multiplication return their exact integer result precisely when it is in range | `I256.checked_eq_some_iff`, `I256.add_eq_some`, `I256.sub_eq_some`, `I256.mul_eq_some` |
| Positive-denominator division agrees with truncation toward zero and cannot escape the input's signed 256-bit range | `I256.truncDiv_eq_tdiv`, `I256.ediv_inRange`, `I256.truncDiv_inRange`, `I256.div_eq_some` |
| The source-equivalent remainder corrections compute mathematical floor and ceiling without trapping under their stated range hypotheses | `FixedPointImpl.mulDivFloor_refines`, `FixedPointImpl.mulDivCeil_refines` |
| The public fixed multiplication and division shapes inherit those refinement results | `FixedPointImpl.fixedMulFloor_refines`, `FixedPointImpl.fixedMulCeil_refines`, `FixedPointImpl.fixedDivFloor_refines`, `FixedPointImpl.fixedDivCeil_refines` |
| Checked signed 128-bit arithmetic returns exact in-range results and rejects an out-of-range product | `I128.checked_eq_some_iff`, `I128.add_eq_some`, `I128.sub_eq_some`, `I128.mul_eq_some`, `I128.mul_eq_none` |
| The `i128` source-equivalent floor and ceiling paths refine their mathematical operations under explicit product and denominator bounds | `I128FixedPointImpl.mulDivFloor_refines`, `I128FixedPointImpl.mulDivCeil_refines` |
| The public `FixedPoint for i128` multiplication and division shapes inherit the refinements | `I128FixedPointImpl.fixedMulFloor_refines`, `I128FixedPointImpl.fixedMulCeil_refines`, `I128FixedPointImpl.fixedDivFloor_refines`, `I128FixedPointImpl.fixedDivCeil_refines` |
| An `i128` phantom overflow or zero denominator returns `none` | `I128FixedPointImpl.mulDivFloor_eq_none_of_product_out_of_range`, `I128FixedPointImpl.mulDivCeil_eq_none_of_product_out_of_range`, `I128FixedPointImpl.mulDivFloor_eq_none_of_zero_denominator`, `I128FixedPointImpl.mulDivCeil_eq_none_of_zero_denominator` |

## Scope and assurance boundary

`I256.lean` models observable checked arithmetic with mathematical integers; `none` represents a Soroban host arithmetic error. `FixedPointImpl.lean` mirrors the control flow and arithmetic of the positive-denominator branches in `src/i256.rs`. `I128.lean` models Rust's checked signed-128-bit results, and `I128FixedPointImpl.lean` mirrors the non-widening `FixedPoint for i128` paths. The proofs establish exact floor or ceiling semantics and absence of arithmetic errors when the product and denominator satisfy the theorem hypotheses. For `i128`, they also establish that an out-of-range intermediate product or zero denominator returns `none`.

The Rust-to-Lean correspondence is human-reviewed rather than generated by verified Rust extraction. Soroban host operations are trusted to implement their protocol-specified signed-256-bit behavior, and Rust checked primitives are trusted to implement their specified signed-128-bit behavior. Negative denominators, the widening `SorobanFixedPoint for i128` fallback, environment object representation, metering, and storage are outside the current model. Downstream applications remain responsible for proving that their inputs satisfy the range and positive-denominator hypotheses.

## Running the proofs

Install the Lean toolchain selected by `lean-toolchain`, then run:

```sh
cd verification
lake update
lake build
```

The proof sources intentionally contain no `sorry`, `admit`, or custom axioms. CI also audits compiled declarations and permits only Lean's standard `propext`, `Classical.choice`, and `Quot.sound` foundations.
